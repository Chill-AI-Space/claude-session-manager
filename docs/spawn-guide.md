# Гайд по спавну сессий

Одно правило: **сессия работает в папке проекта — `~/Code/<имя-репозитория>`.**
Никаких одноразовых папок, никакого `$PWD` случайной сессии.

## Куда реально попадает сессия

`POST /api/sessions/start` перед запуском агента разрешает путь через
`resolveProjectPath()` (`src/lib/project-path.ts`):

| Что передали | Куда попадаем |
|---|---|
| Обычная существующая папка (корень репо, подпапка) | Как есть — ничего не меняется |
| Worktree-путь: `…/.worktrees/<repo>/…` или linked worktree | `~/Code/<repo>`, если такой папки нет — основной чекаут, которым владеет worktree |
| Путь не существует | `~/Code/<basename>` — папка создаётся, если её раньше не было |
| Worktree-путь, а проекта нигде нет | `~/Code/<repo>` создаётся: `git clone <origin>`, если URL удалось узнать, иначе пустая `mkdir` |

Порядок важен: сначала ищем папку проекта в разделе код, потом владеющий
чекаут, и только потом создаём. Проект, который уже существует где-то ещё,
не дублируется клоном.

Проверить, что сработало: первый `status`-событие SSE содержит заметку
(`project folder: …` / `owning checkout: …` / `cloned … → …` / `created …`),
в логах — запись `session_project_resolved`.

## Worktree — только когда нужна изоляция

По умолчанию worktree **выключены** (`sessions_worktree_default = "false"`,
одинаково для браузера и для curl-подсессий). Поэтому спавн больше не плодит
`~/Code/.worktrees/<repo>/<слаг>-<таймстамп>/`.

Включать явно, только когда параллельные сессии реально мешают друг другу
(грязный индекс, параллельные PR, чужой checkout переключается под ногой):

```json
{ "path": "/Users/vova/Code/myrepo", "message": "…", "worktree": true }
```

Worktree создаётся как `<repo>/../.worktrees/<repo>/<слаг>-<ts>` с веткой
`session/<слаг>-<ts>`. Чистка: **Settings → Session Worktrees**
(`GET /api/worktrees` — список с причинами, `POST /api/worktrees` — удаление;
сносятся только чистые ветки без незапушенных коммитов).

Правило: **не передавай worktree-папку «чтобы изолироваться»** — для этого есть
флаг `worktree: true`. Передавай корень проекта.

## Рецепт: подсессия через curl

```bash
curl -s -N -X POST http://localhost:3000/api/sessions/start \
  -H "Content-Type: application/json" \
  -d '{
    "path": "'"$(git rev-parse --show-toplevel)"'",
    "message": "Implement issue #N: <title>",
    "agent": "opencode",
    "reply_to_session_id": "YOUR_SESSION_ID"
  }'
```

- **всегда `-N`** — без него SSE-поток буферизируется и `session_id` не виден;
- достаём id: `grep -o '"session_id":"[^"]*"' | head -1`;
- `path` = корень репозитория. Если под рукой worktree или чужая сессия —
  передавай всё равно корень либо вообще `$PWD`: путь развернётся в проект;
- `agent`: `opencode` — дефолт (дёшево), `codex` — сложный рефакторинг,
  `claude` — только архитектура/ревью;
- работать «в той же папке» можно и нужно — параллельные сессии одного репо
  теперь делят один чекаут. Изоляцию включай флагом, а не другой папкой.

## Чего не делать

- Спавнить в `/tmp`, `~/Library/...`, в `$PWD` непонятной сессии — оттуда и
  берутся бессмысленные папки.
- Создавать папку вручную «чтобы было отдельно» — это то же самое загрязнение.
- Пушить в ветку чужой сессии/PR. Сессия = своя ветка + свой PR
  (см. `.githooks/pre-push`, правило immutable PRs).

## Быстрая диагностика

```bash
# что реально возвращается при старте (первые события)
curl -sN -X POST http://localhost:3000/api/sessions/start \
  -H "Content-Type: application/json" \
  -d '{"path":"'"$PWD"'","message":"ping","agent":"opencode"}' | head -5

# сколько worktree-папок накопилось
find ~/Code/.worktrees -mindepth 2 -maxdepth 2 -type d | wc -l
```
